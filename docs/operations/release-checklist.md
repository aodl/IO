# Release Checklist

Use this before every release-oriented commit or artifact proposal.

- [ ] `cargo fmt --all -- --check`
- [ ] `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- [ ] `cargo check --workspace --all-targets`
- [ ] `cargo test --workspace`
- [ ] `cargo check -p io-stream-manager -p io-nns-neuron-manager --target wasm32-unknown-unknown`
- [ ] `cargo run -p xtask -- did_surface`
- [ ] Finalize and commit the exact source tree, then run `tools/scripts/build-release-from-source <SOURCE_COMMIT>` from the artifact-recording checkout.
- [ ] Commit the generated artifact set in the commit immediately after source finalization. That artifact-recording commit may change only `release-artifacts/**`.
- [ ] Keep every later release-tail commit limited to immutable local evidence under `deploy/local-sns-rehearsal/evidence/**`, `docs/**`, `.github/workflows/**`, or `tools/sns/launch-readiness.toml`. Validator, lifecycle-tool, release-generation, dependency, Rust/toolchain, canister, crate, and frontend build-input changes require a new source-finalization/artifact pair.
- [ ] Read the exact source-finalization commit from `release-artifacts/manifest.json`, prove its immediate artifact-recording child from Git history, and preserve both identities exactly throughout review and integration. Later evidence/documentation-tail commits are not artifact-recording commits.
- [ ] Before integration, prove the pull-request head is the checked-out `HEAD` and the current PR base commit is an ancestor of it. Do not merge the base into the branch or rebase the branch to repair a failed ancestry check, except for the single graph-only reconciliation defined below.
- [ ] Require test, security, and reproducible-build to succeed on that same exact release-tail SHA. A successful ancestor run is not current-head release evidence.
- [ ] One ancestry-reconciliation merge may follow the validated release tail only when machine checks prove: the base is absent solely by graph shape; its complete tree equals a commit already ancestral to the release; their diff is empty; the merge's first parent is the exact validated release-tail head and its second parent is the exact reviewed base; the merge tree equals its first-parent tree; source-finalization, immediate artifact child, evidence package and selector identities are unchanged; `test_ci` and `verify_release` pass on the merge head; and hosted test, security and reproducible-build pass on that exact head. This exception is forbidden for any content-bearing base.
- [ ] Integrate this release lineage only by a direct fast-forward of `master` after every required workflow passes on the exact release-tail head and explicit integration authorization is given. No squash merge, rebase merge, ordinary added merge commit, or ordinary GitHub merge-button integration is permitted. If branch protection makes direct fast-forward integration impossible, do not merge and do not weaken provenance; return for an explicit decision. If resolving an advanced base requires build-input changes, create a new source-finalization/artifact-recording pair and rerun release validation.
