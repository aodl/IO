# Simplified launch threat model

IO is pre-launch. Controls below are source and local-test properties; they do
not replace final configuration review, independent audit, or separately
authorized mainnet operations.

| Threat / protected invariant | Attack precondition | Runtime mitigation | Executable evidence | Operational mitigation / residual risk |
|---|---|---|---|---|
| Unauthorized or duplicate monetary intent | Caller tries another identity, nonce, destination, or replay | Exact caller authority, canonical Account binding, request fingerprint, and per-caller nonce/result replay | Stream `redemption::semantic_validation_rejects_fingerprint_intent_and_phase_corruption`; PocketIC redemption/replay tests | Monitor rejects. A caller may retry its exact request; it cannot choose protocol destinations. |
| Async callback race or duplicate effect | State changes while an inter-canister call awaits | Persisted typed phase/intent first; callback applies only to exact operation, phase, dispatch epoch, and fingerprint | Manager reverse-callback and transfer retry tests; workspace PocketIC recovery suites | Rare ambiguity pauses for exact proof; no global absence reconstruction. |
| Adversarial cycles consumption through permissionless APIs | Repeated premature reward, backing, idle resume, or Jupiter calls | Reward observation consumes the existing due bit before external reads; idle NNS resume is local; activation-floor and completed-block checks are local; no per-caller/probe allocation | Reward due/call-counter tests, NNS idle result test, and Jupiter floor/call-counter tests | Follow [cycles operations](../operations/cycles-management.md). Backing and new at-or-above-floor Jupiter proof calls can still consume bounded external reads; monitor call and burn rates. |
| Jupiter historical/pre-activation replay | Attacker knows an old valid-looking route block | Immutable nonzero activation floor checked before Ledger/archive; exact source/destination/fee; permanent successful-block replay state | NNS Jupiter activation and `processed_jupiter_block_replays_exact_typed_result` tests | Audit the launch floor. Completed replay state grows only after successful canonical deposits. |
| Arbitrary invalid Jupiter proof probing | Permissionless caller supplies unlimited unrelated indexes | Below-floor and completed indexes are local; an at-or-above-floor lookup is canonical, bounded, and creates no negative-cache or throttle state | NNS activation and ledger call-counter tests | Investigate abnormal call/burn rate. Repeated fresh invalid indexes remain a cycles/liveness risk but cannot fabricate monetary proof. |
| Redemption uses an adverse stale quote | Supply, excluded IO, reserve reflection, fees, or liquid ICP changes after IO pull | Fresh pre-payout sequential reread; named invariant rejects observed adverse drift before payout intent; post-payout checks remain | `pre_payout_conditions_reject_adverse_and_accept_conservative_drift` plus mocked-ledger payout-call tests | Supply increases and excluded-balance decreases require pause plus active-work drain. The reread is defence in depth, not a cross-canister atomic lock. |
| Runtime principal or Account alias | Bad install args bypass offline tooling | Pairwise control-principal separation and ledger-namespace Account collision checks in each canister | `every_control_principal_pair_must_be_distinct`, Stream Account-collision and NNS launch/account-role tests; production-wiring validator | Independently review final Accounts/principals. Cross-ledger tuple equality alone is not treated as aliasing. |
| Reward IO transfer succeeds but SNS refresh fails | Governance rejects, times out, decodes incorrectly, or returns another neuron | Ledger transfer is monetary completion; `refresh_attempted` is persisted before await; one best-effort call is inspected and bounded-log failure never repeats IO or blocks settlement | PocketIC ledger/manage-neuron call counters across success, rejection, transport, malformed, and wrong-ID outcomes; stable maximum-state test has no refresh queue | Monitor bounded canister logs. Later reward delivery naturally attempts refresh again; no eventual refresh guarantee or durable retry queue exists at launch. |
| Pooled parent configuration or maturity drifts | Parent has the wrong delay/followee/auto-stake/state, or staging capture conflicts with canonical custody | Exact lazy-bootstrap proof, fixed following policy, pre-command balance baseline, role-specific Account, canonical finalization boundary, and once-frozen positive delta | parent configuration, follow, replay, maturity capture, donation, and cross-Account isolation tests | Drift blocks new maturity/reconciliation without discarding submitted effect evidence; donations intentionally inherit Account semantics. |
| Ambiguous outgoing effect is retried | A Ledger transfer, Split, or child Disburse succeeded but its response was lost | Persist immutable intent before the call and require exact canonical effect proof before another submission | transfer recovery, Split embryo, child Disburse, and cached-stake reflection suites | Without exact effect proof, a retry could send value twice or create a second child. No analogous provenance proof exists for fungible ICP already in IO custody. |
| Controller, release, or CI supply-chain compromise | Wrong controller/module/source/artifact or ancestor CI is presented | Exact controller/module pins, deterministic source commit, immediate artifact lineage, exact-head checks, manifest hashes, production DID/debug separation | `validate_production_wiring`, `verify_recorded_source`, `verify_artifacts`, `did_surface`, reproducible-build workflow | Require independent review and all required hosted workflows on the exact integration head. Compromise of all authorized release actors remains residual. |
| Stable-memory or state-growth exhaustion | Public calls allocate indefinitely or retained proofs accumulate | Bounded vectors/history, one Stream monetary slot, one NNS immediate command, at most 32 live cohorts, one pending batch, and a 1,000-record neuron registry; resolved children retire independently | maximum stable-cell, 32/33 capacity, registry-bound, Historian-bound, and stable-schema tests | Monitor stable size and authenticated replay maps. Successful canonical deposit/redemption replay evidence remains a lifetime capacity input. |
| Start/cancel spam creates repeated fees | SNS state flips while pooled principal is reconciling | Precommit cancellation nets without an effect; split commitment is sticky; one cohort per daily generation; reward re-entry is prospective | cancellation, overlapping-generation, and committed-restake tests | Capacity is 32 and is not a liquidity SLA. |
| Illiquid redemption pulls claimant IO | Solvency includes pooled/unwind/transit backing but liquid ICP is short | Quote uses `B/C`; a separate `L` check returns typed shortfall before nonce/slot/IO pull | liquidity-shortfall and retry-after-return tests | Caller retries after global liquidity returns; no queue or discounted rate. |
| External canister/module/parameter drift | Ledger fee/standards, Governance module/parameters, Root topology, or NNS neuron state changes | Readiness and each relevant operation re-read canonical sources; exact expected modules/fees/parameters; drift pauses or fails closed | lifecycle/readiness unit and PocketIC suites; `validate_historian_freshness` | Pause around reviewed governance/treasury changes and investigate source drift. Availability depends on external canisters. |
| Historian stale/error data is treated as monetary truth | Observer is stale, compromised, or partially refreshed | Historian is read-only/non-authoritative; missing/stale/error is never zero; monetary canisters query canonical sources directly | Historian freshness/coherency tests and `validate_historian_freshness` | Dashboards retain last-known-good values with explicit health. Observation availability remains residual. |
| Stale, mixed, or ambiguous release artifacts/evidence | Artifact was built before claimed source, evidence is rebound, or CI belongs to another SHA | Manifest records exact source; independent rebuild comparison; immutable historical packages plus explicit current selector; release-tail path rules | artifact-lineage and current-selector xtask tests; `verify_recorded_source`; committed-evidence validator | Do not edit historical evidence. Source changes require a new source/artifact/current-evidence lineage before release. |
| Stable decode accepts obsolete development state | Pre-launch bytes use removed shapes/defaults | Each production canister accepts exactly launch V1; corrupt, immediately preceding development V1, or future bytes reject; no fallback decoder or compatibility defaults | Per-canister old-V1/corrupt/future tests, round-trip/reopen tests, and `validate_stable_storage` | Pre-launch installs may be discarded/reinstalled. Any post-launch migration requires a separate design. |

Production activation, controller handoff, cycles funding, final SNS identities,
mainnet testflight, and mainnet operations remain unavailable until separately
reviewed and authorized.
